ExoStack: configure a wearable robot, don’t rewrite it

An open-source ROS 2 framework that takes a wearable robot from body-worn sensors to assistance at each joint, with human-in-the-loop personalization built in. A new device, with more joints, both legs or different hardware, is configured rather than coded.

The idea

Every wearable-robot study rebuilds the same software: drivers for body-worn sensors, time alignment across boards, gait-event detection, assistance profiles, actuator commands and, increasingly, the machinery of human-in-the-loop optimization. A new sensor or joint usually means editing tightly coupled code.

ExoStack provides that pipeline as an open framework. Boards are declared rather than programmed, every ROS 2 node is created from one YAML entry, and sensors, actuators and algorithms are added from templates without touching the core.

My role

  • Designed and built the framework end to end: ESP32/micro-ROS firmware (ESA), the ExoCore ROS 2 package and the PASE configuration GUI.
  • Implemented declarative device lists, self-registering drivers, plug-in algorithms and one profile path shared by deployment and HIL optimization.
  • Benchmarked it on three embedded computers, validated it on knee and hip exosuits, and released it with a documentation website and user manual.

01System overview

Three modules, one ROS 2 graph

ESA (Embedded Sensing and Actuation) runs on ESP32 boards worn as hubs on the limbs, linked to ROS 2 through a micro-ROS agent over Wi-Fi or USB. ExoCore, on the host computer, turns hub data into gait events, assistance profiles and actuator commands, and closes the HIL loop when personalization is needed.

Its nodes are created from YAML entries and run plug-ins selected by name, all kept in exo_stack_resources, which PASE edits before launching them. Because commands are ordinary ROS 2 topics, any actuator with a ROS 2 driver can be used as well.

02Embedded sensing and actuation

Declare the board, don’t program it

A hub is a short Arduino sketch: a deviceList[] with one row per device (analog, digital or I²C, pin or address, label, filter) and five calls in setup() that open the link, configure the devices, declare the node, publishers and actuators, and arm a 3 s watchdog.

Every channel of a hub travels in one message on one time base. Drivers are header–source pairs registered with a single macro, so a new sensor is one file pair; drivers ship for the BNO085 IMU, NAU7802 load-cell amplifier, AS5600 encoder, a Festo proportional regulator and a servo.

03ExoCore ROS 2 nodes

Small nodes, one YAML entry each

Six executables (synchronizer, gait-event detector, motion planner, profile node, cost evaluator and HIL optimizer) are started once per configuration entry. A bilateral hip exosuit, for example, gets four detectors, a planner and a profile node per hip, and a cost and optimizer node for each profile switched to HIL.

The synchronizer tares every hub clock with a trigger and publishes named, time-matched channels, so algorithms ask for signals by name. The candidate number k travels in the profile, status and cost messages, so the optimizer only ever accepts the cost of the candidate it proposed.

04From lookup row to set-point

Assistance that never changes mid-stride

Each joint has a planner and a profile node. The planner restarts its profile at every gait event and plays it against time or an external gait-phase estimate; a newly received profile waits in a buffer until the current one ends.

In deployment a lookup plug-in maps walking speed, and optionally intent, to a table row; a builder shapes it into triangular, trapezoidal or N-point waypoints; linear, overshoot-free PCHIP or polynomial planners play them. In HIL mode only the source of the parameters changes, so a personalized set enters daily use as a new table row.

From U3ExoStack · arXiv preprint

Design principle

One profile interface: a lookup-table row at deployment and an optimizer’s candidate during personalization travel the same path to the actuator.

05Configure · launch · see

An experiment without editing files

PASE is a PyQt5 application with three tabs: linked editors for the four YAML files, a launch view that starts the micro-ROS agents and the six stages in order and shows which nodes are alive, and live plots of any topic field with gait events drawn as markers.

06Benchmarks

Holding rate on small computers

Each test hub carried ten devices (two I²C sensors and eight analog inputs) publishing at 100 Hz, on a Jetson AGX Orin, a Jetson Orin Nano and a LattePanda Delta.

  • Up to eight hubs per computer: 99.5 ± 0.018 Hz observed, jitter about 1.8 µs
  • Jetson AGX Orin: 99.6–99.9% of 200–500 Hz planner targets, mean latency 8–21 ms
  • At 200 and 300 Hz all three computers held at least 97% of the target, below 18 ms

07Validation on hardware

A knee suit and a hip suit, one code base

Both exosuits are driven by pSTAMs through proportional pressure regulators and differ only in device lists, YAML files and plug-ins. On SoftEXOwalk, Bayesian optimization tuned the amplitude and onset delay of a trapezoidal knee-flexion profile to maximize assistive force. On the hip exosuit, four backpack pSTAMs pull through tendons, and CMA-ES tuned delay, rise, hold and fall times to maximize the ratio of assistive to resistive force.

In both, resistive force stayed below 15 N, hubs ran at 100 Hz, assistance was personalized for each speed and leg, and deployment drew profiles from speed lookup tables for 3.5–5.5 km/h.

08Open source · supplementary materials

Code, documentation and manual

The paper’s supplementary materials are the complete ExoStack v1.0 code base and its user manual. The repository holds the ESA library, the ExoCore ROS 2 package, the resources folder and the PASE GUI, each with its own install steps; it is tested on Ubuntu 22.04 with ROS 2 Humble.

The documentation website walks through installation, every configuration file, the GUI and step-by-step guides for adding sensors, actuators and algorithms, with every ROS 2 topic and message layout. The same content is available offline as the user manual (PDF).
